# Автоматизация бизнес-процесса с LLM «от входа до действия»

**Проблема:** ручная обработка входящих = потери и задержки.  
**Решение:** LLM структурирует в JSON + контроль качества + аудит + действие.  
**Результат:** быстрее обработка, меньше ошибок, прозрачность.

---

## СеверСнаб: от письма клиента до черновика заказа

Управляемый кейс для портфолио: один процесс B2B-дистрибьютора, от входящего письма до действия.

Конвейер: **вход (файлы) → LLM (строгий JSON) → проверка → действие (JSON-файлы)**. Модель структурирует заявку. Политика решает, можно ли создать черновик заказа, нужно ли отдать письмо менеджеру или это вообще не заявка.

Кейс = проблема + ограничения + контекст + результат + защита. Разбор для заказчика и защита — в [docs/case.md](docs/case.md). Оффер на пилот и блок для найма — в [docs/offer.md](docs/offer.md). Как устроен конвейер — в [docs/process.md](docs/process.md).

Компания, клиенты, ИНН и домены вымышлены. Ответы модели в сборке — контрольные фикстуры, часть из них специально ошибочна. Так проверяется не «красивый ответ», а умение системы отказать.

## Соответствие MVP курса

- вход: чтение писем из `data/inbox/` по команде;
- LLM: системный промпт «аналитик процесса», схема JSON (`intent`, `category`, `summary`, `priority`, `next_action`, `fields`, `confidence`, `escalate`), temperature **0.2**;
- контроль качества: валидация схемы, `confidence=low` / `data_gaps` / битый JSON → эскалация, плюс коммерческие гейты;
- журнал: `out/audit.jsonl` хранит **вход + результат + статус**;
- действие: файлы результата в `out/orders|escalations|closed/`.

## Что получается на контрольном ящике

10 писем, совпадение с эталоном 10/10.

- 3 черновика заказа, проведение в учёт запрещено;
- 6 эскалаций: чужой адрес, додуманное количество, неизвестный клиент, лимит, дата в прошлом, неоднозначная бумага;
- 1 благодарность закрыта без заказа.

Три черновика из десяти — не доля автоматизации. Шесть писем обязаны были остановиться. Окупаемость считается отдельно, из вводных, и в целевом контуре даёт 115 229 ₽ в месяц при окупаемости фикса за 1,6 месяца. Осторожный контур — 99 231 ₽ и 1,8 месяца. Обе цифры — гипотеза, не замер.

## Запуск

Нужен Python 3.11 или новее. Зависимости ставьте в локальный `.venv` проекта.

### Запись демо (без ключей и без расхода токенов)

```powershell
.\.venv\Scripts\Activate.ps1
python -m case_lab demo
```

`demo` очищает `out/`, прогоняет 10 писем на фикстурах и пишет `out/report.md`.  
Это удобный контур для **записи экрана**; та же бизнес-логика, что и в боевом режиме.

```powershell
python -m pytest
```

### Боевой контур (Proxy API)

LLM ходит через **Proxy API**, не напрямую в OpenAI.

1. Скопируйте `.env.example` → `.env`
2. Укажите ключ Proxy API в `OPENAI_API_KEY`
3. Проверьте URL: `OPENAI_BASE_URL=https://api.proxyapi.ru/v1`
4. Модель: `OPENAI_MODEL=gpt-4o-mini`
5. Включите живую модель: `CASE_LLM=live`
6. Запуск боевого контура (файловый вход + уведомления в `out/notifications/`):

```powershell
python -m case_lab live
```

Без ключа `live` не стартует.

#### Точки подключения

| Слот | Переменная | Статус |
| --- | --- | --- |
| Файловый вход | `CASE_INPUT=files` | работает |
| HTTP `POST /ingest` | `CASE_INPUT=http` + `python -m case_lab serve` | каркас готов (нужен `.[api]`) |
| Почта IMAP | `CASE_INPUT=mail` + `MAIL_*` | слот, ждёт доступы |
| Уведомление файлом | `CASE_NOTIFY=file` | работает |
| Уведомление email | `CASE_NOTIFY=email` + SMTP | слот, ждёт доступы |

HTTP-сервер (только если нужен `POST /ingest`):

```powershell
python -m pip install -e ".[api]"
python -m case_lab serve
```

Для записи демо и сдачи MVP **`.[api]` ставить не обязательно**.

### Планировщик (опционально, аналог cron)

Скрипт сам запускает боевой контур: `scripts/run_scheduled.ps1`  
(на Linux/macOS — `scripts/run_scheduled.sh`).

Ручная проверка:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_scheduled.ps1
```

В Планировщике заданий Windows:
1. Создать задачу → триггер, например каждые 10 минут.
2. Действие: запуск программы `powershell.exe`
3. Аргументы:

```text
-ExecutionPolicy Bypass -File "D:\CASE_LAB\scripts\run_scheduled.ps1"
```

4. В `.env` к этому моменту должны быть рабочие `CASE_LLM` / ключ Proxy API (если `live`) и `CASE_INPUT=files` или другой готовый вход.

Это не отдельная логика кейса, а «будильник» вокруг команды `case_lab live`.  
Повтор уже обработанных писем второй заказ не создаёт.

### Что означает `.env` (что заполнять сейчас, что потом)

Шаблон: `.env.example`. Рабочая копия: `.env` (в git не попадает).

| Переменная | Зачем | Сейчас |
| --- | --- | --- |
| `CASE_LLM` | `replay` = фикстуры для записи экрана; `live` = вызов модели | для демо: `replay` |
| `OPENAI_API_KEY` | ключ **Proxy API** | нужен только при `live` |
| `OPENAI_BASE_URL` | endpoint proxy | уже `https://api.proxyapi.ru/v1` |
| `OPENAI_MODEL` | модель в кабинете ProxyAPI | `gpt-4o-mini` |
| `CASE_INPUT` | откуда брать заявки: `files` / `http` / `mail` | для демо: `files` |
| `MAIL_*` | вход из почтового ящика | слот на потом, можно пустым |
| `CASE_NOTIFY` | куда отдать итог менеджеру: `file` / `email` / `none` | для демо: `file` |
| `MANAGER_EMAIL` | email менеджера | только если `CASE_NOTIFY=email` |
| `SMTP_HOST` / `SMTP_USER` / `SMTP_PASSWORD` / `SMTP_PORT` | сервер **исходящей** почты, чтобы отправить письмо менеджеру | слот на потом; при `CASE_NOTIFY=file` не нужны |

Важно:
- `demo` и `live` / `serve` — это **разные команды**, не разные «программы»;
- при появлении ключа Proxy API для LLM код менять не нужно — только `.env` и `python -m case_lab live`;
- почта IMAP и SMTP-письмо менеджеру — слоты: доступы в `.env` + небольшая доработка адаптера, когда появятся реальные пароли.

## Куда смотреть

| Файл | Зачем |
| --- | --- |
| `data/inbox/` | письма заказчика |
| `data/cassettes/` | что «ответила» модель, включая нарочные ошибки |
| `data/golden/` | эталон: решение после политики, не сырой ответ модели |
| `src/case_lab/gates.py` | правила, которые имеют право остановить заказ |
| `src/case_lab/actions.py` | черновик, эскалация или закрытие |
| `out/audit.jsonl` | журнал: вход + результат + статус, гейты и отпечаток |
